# Course registration and delivery mode

The home action 可登录课程 opens the native Monday–Friday week grid with periods 1–5. The school WebView is a background transport, invisible and excluded from accessibility. The main screen shows actual candidate names or a candidate count in each cell; tapping a cell opens native details with course code, offering faculty (開講学部), schedule, teacher and the school's remote-delivery marker. Missing credits are left blank. Weekend and intensive candidates remain available in a separate native list.

The current school layout exposes candidate lists through 未登録 / 追加登録 links per time slot, with a 登録 button per course. `school-registration-native.js` discovers those live links, reads each list without selecting or submitting, and returns to the verified timetable between lists. It derives year and quarter from the school page, supports fifth-period candidates, and does not add the sixth period. A read failure is not treated as an empty list: the UI reports incomplete slots and refresh reads them again. Courses appear progressively while scanning, and selection is enabled when scanning finishes. The school original page is available only as an optional item in the status dialog.

The native page allows multiple selections across cells and within one cell. The confirmation lists all selected courses with their offering faculties. After one approval, a sequential queue sends all selected courses through the school's per-course flow. It waits for each response/navigation before sending the next course, without asking the student to verify each enrollment. After the last response it reloads the school entry and queries the whole batch once. Unexpected school confirmation prompts are cancelled, stop further sending and lead to consolidated verification; they are never blindly accepted. Before dispatch, the activity reloads the live grid, checks student and term, reopens the exact slot and compares the course signature (code, department key, title, offering faculty, schedule, teacher, delivery marker, credits and availability). The adapter clicks only the observed matching row button belonging to a same-origin school form. It never synthesizes a submission URL or executes an extracted handler string. The row handler's second argument is a school department key, not a quarter number.

Candidate pages omit the student number. They are accepted only after this WebView verifies the current grid identity and term and records a short-lived, per-tab context for the requested slot. Account changes, login pages, wrong slots, changed years, malformed lists and foreign form actions fail closed. Persistent pending state prevents retries after uncertain requests or process death. The full approved list, attempted IDs and dispatched IDs are saved before/after each send. Dispatch alone never establishes success. Connection failures, changed course information or ambiguous dispatch stop further sending and trigger one final read-only query; a course missing from an intermediate timetable does not interrupt the batch. The final native result panel lists registered courses, attempted courses absent from the school timetable, and unsent courses. After a restart, pending batches are queried automatically and never resumed for submission. If the result query fails, pending state is retained and the retry button only queries; there is no manual acknowledgement that can clear unknown state. A result is successful only when the verified live timetable contains the selected course code in the same account and term. Read-only sync never clicks registration buttons. Real enrollment is not tested without the student choosing and confirming a course.

Foreground synchronization still reads registration status independently. Its read-only snapshot cannot enable native submission and does not reset the candidate notification baseline. Native candidate snapshots and alerts are keyed by student; repeated identical candidate reads do not notify again. Diagnostics record stages, slot progress and counts without account identifiers, page contents or authentication URLs.

Verification: `node scripts/test-school-registration-native.cjs`, `node scripts/test-school-registration.cjs`, Android unit tests, release lint, and device checks of native list rendering. Simulated submission tests establish guarded dispatch behavior, not school acceptance of an enrollment.

Delivery mode is now extracted from the value cell of オンライン授業／対面授業 in the school syllabus. Timetable sync only captures observed syllabus links, without issuing requests or waiting on syllabi. After all timetable and notice/registration queries finish, a separate final phase follows those links with two bounded read-only requests at a time. Its timeout never marks an already saved timetable failed. Values are saved by student, academic year and exact course code, and feed calendar blocks and exports. Real-time online, on-demand online, face-to-face and blended courses remain distinct. Previously reviewed cohort/session-specific exceptions retain their constraints. Missing data does not imply online delivery; existing saved data survives fetch failure.

Verification: `node scripts/test-school-registration.cjs`, `node scripts/test-school-syllabus.cjs`, Gradle `testDebugUnitTest` and `lintRelease`. The screenshot's course title is not used to guess a course code.

## Calendar navigation correction

Date-picker, month navigation, month day selection and previous/next week now use one date transition. It updates the date, displayed month and term together; the week number is derived from that date rather than stored independently. Manual year/term selection moves the date to that term's first displayed week. Previous/next week remains enabled across term boundaries.

Both week and month views use the current student's resolved events from all saved terms, deduplicated by date, period and course code with newest snapshots taking precedence. This keeps adjacent-term courses visible in a boundary week/month. Classroom and delivery labels retain each event's original year/term key. Navigation into an unsupported year never creates course events. Exports remain explicitly scoped to the selected term.

`SchoolCalendarNavigationTest` covers Q2-to-Q3 date selection, bidirectional week movement, Q4 across January, term-anchor round trips, mixed Q3/Q4 boundary weeks, monthly event inclusion and duplicate suppression.


The native candidate page now displays the remaining registerable credits returned by the school's current-quarter summary, separately from annual and already-registered credits. Visible school refusal messages and informational alerts are preserved per attempted course for the final report. A completed verification reports registered and unregistered courses explicitly; it no longer leaves a completed refusal described only as sent. Missing quota information is unknown, never zero. School restrictions are not bypassed.

Timetable imports preserve the exact visible course-name line separately from instructor text, using the same verified school document. Calendar matching prefers that exact title; older snapshots retain conservative matching until refreshed. This fixes engineering titles with department qualifiers such as 【情報】 without weakening partial-name or ambiguous-code safeguards. Classroom coordinates remain account, academic year, date, period and course scoped; delivery-mode labels still take precedence over physical rooms for online courses.
